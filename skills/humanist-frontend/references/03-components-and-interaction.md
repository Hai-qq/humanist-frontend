# 3. 组件与交互契约

## 从产品案例迁移到行为约定

**材料线索**：Kimi 的自动标题、输入建议和历史跳过入口案例展示了辅助操作的不同形式；Researcher 的设计记录讨论信息呈现的取舍。[K9] [K10-R1] [K8] [K3]

**综合判断**：辅助应减少整理负担，同时保留人的编辑权与对当前状态的理解。案例未说明的请求竞态、失败恢复与取消确认，是本项目补充的工程约束。

**如何应用**：例如研究笔记自动命名：正文先独立保存，生成标题作为辅助元数据；用户改名后保留其名称，生成失败不阻断阅读。这个例子展示迁移方法，不描述 Kimi 的完整内部实现。没有自动命名的页面无需增加该功能。

**如何检验**：在失败、迟到响应和切换对象后，用户的输入是否仍在、对象是否正确、下一步是否明确？精致默认态不能替代这些行为检查。


组件不是只有默认外观。实现前列出当前功能实际存在的状态，并为每种状态确定内容、可用动作、焦点和恢复路径。不需要让静态展示卡片拥有一套无用的服务器错误状态；也不能因为只有一张设计稿就省略保存失败。

## CMP-01 · 常用组件

| 组件 | 内容与视觉规则 | 行为与必须检查的状态 |
|---|---|---|
| 主按钮 | 一个动作一个名称；同一局部流程有明确主次；主要按钮使用操作色 | hover/pressed/focus/disabled/pending；异步提交防重复；宽度不因 spinner 突变 |
| 次按钮/文字操作 | 层次低于主动作，但不把低对比当成“次要” | 有可访问名称；链接用于导航，按钮用于动作；不只在鼠标悬停时可用 |
| 输入与文本域 | 可见 label；帮助与限制靠近字段；placeholder 不能代替标签 | focus/invalid/disabled/read-only；错误关联字段；失败不清空输入 |
| 选择与建议 | 少量简单选项优先原生 select；可搜索建议区分输入值与候选值 | 正确的组合框语义与键盘模型；无结果和加载不同；Esc 不丢弃已输入内容 [N9] |
| Tabs | 代表同一上下文中的不同面板；不是随意给导航加 role | tablist/tab/tabpanel 关联；方向键导航；有加载延迟时避免焦点一到就昂贵切换 [N10] |
| 导航与侧栏 | 当前对象清楚；工作层级不深于任务必要范围 | active 不只靠颜色；收起后关键功能仍可访问；可访问名称不随图标消失 |
| 对话框 | 标题、结果影响、动作明确；不滥用模态 | 打开时合理移动焦点，Tab 不进入背景，关闭后合理归还焦点；Esc 与取消结果一致 [N8] |
| 非模态浮层 | 小菜单、提示与筛选采用与触发器关联的位置 | 不误用模态锁焦点；避开视口边缘；触屏/键盘可以操作 |
| 状态提示 | 简短、具体，显示真实结果；关键失败不能仅靠瞬时 toast | 更新可被辅助技术感知；不无故抢焦点；必要错误可再次查看 [N6] |
| 列表/表格 | 字段语义、单位、排序依据明确；选中与 hover 分开 | 有表头和排序说明；选择不因刷新随机丢失；空数据与筛选无结果不同 |
| 数据图 | 坐标、单位、时间范围、来源与缺失值可理解 | 颜色之外有标签/线型；提供可访问数据或摘要；不得伪造数值或用 0 代替缺测 |

工具提示不承担唯一的必需说明。原生按钮和输入优先于自己用 `div` 模拟；复杂组合部件优先复用项目已有且符合键盘语义的实现。第三方组件库的名称本身不保证你组合后的页面可访问。

## CMP-02 · 输入、保存与反馈

长文本编辑保存草稿；自动保存需要明确“未保存/保存中/已保存/失败”状态与恢复方法。必须区分请求送出、服务端确认和真正持久化的成功；不能 `setTimeout` 后无条件显示“已保存”。网络失败说明是否可以重试以及输入是否保留。

中文等组合输入进行中，Enter 不能误触提交。监听事件时结合组合输入状态与目标浏览器实际行为，覆盖 compositionstart/compositionend 场景；使用框架时注意 nativeEvent 与合成事件的区别。这是本规范的工程验收要求，不是从品牌手册抽取的样式规则。

多字段表单先验证可确定的约束；提交失败后将注意力引到第一个实际错误或错误摘要，避免每输一个字符就打断用户。对禁用动作给出原因，不能只把按钮灰掉让人猜。

## CMP-03 · 三种“空”不能画成一个页面

首次使用的空状态说明下一步；筛选无结果保留筛选条件并可清除；加载失败保留已有信息并提供恢复。骨架屏用于可预测的结构，不能伪装成真实数据。权限不足与系统故障分开说明，不暴露不应公开的内部信息。

示例：

| 不清楚 | 更可执行 |
|---|---|
| 暂无数据 | 还没有项目。新建项目后，可以添加文件。 |
| 操作失败，请稍后再试 | 项目未保存。连接已断开，输入仍保留在此页面。恢复连接后重试。 |
| 确定 | 保存规则 / 删除项目 / 继续运行（根据真实动作选择） |
| AI 正在努力思考 | 正在读取 3 个已选择文件（仅在后端确有该状态时显示） |

示例文案只在事实成立时使用。未实现草稿保存，不能写“输入已安全保存”。

## AGT-01 · 长任务有可理解的状态模型

存在长时间运行时，至少区分适用的 `idle / queued / running / needs-input / cancelling / succeeded / failed / cancelled`。界面文字不是后台状态机的替代品；状态转换由真实事件驱动。

| 当前状态 | 用户看到什么 | 可以做什么 | 不可声称什么 |
|---|---|---|---|
| queued | 已排队；仅在真实可得时显示队列位置 | 取消排队或修改未执行输入 | 无依据的预计完成时间 |
| running | 当前已知阶段、已完成结果或活动记录 | 查看详情；存在能力时停止 | 伪百分比、虚构工具调用、虚构内部思考 |
| needs-input | 缺失信息/待批准动作与影响范围 | 编辑、允许、拒绝 | 用户沉默代表同意 |
| cancelling | 已提出取消；等待执行端确认 | 查看已产生结果 | 尚未确认就写“已停止” |
| failed | 失败范围、保留内容、可恢复条件 | 安全重试、修改输入或返回 | 将部分失败整体标成成功 |
| succeeded | 结果、保存位置和必要来源 | 查看、导出、继续编辑 | 下载完成就等同部署成功 |

只能中断前端流式显示、不能取消后端任务时，按钮和提示必须说明这一边界。重试存在付费或外部副作用时，先检查幂等性和已完成部分；不要把普通“重试”设计成隐式再次扣费或重复写入。

## AGT-02 · 渐进披露不等于隐藏问题

主区展示与用户当前任务相关的内容，活动和技术日志可折叠，错误与待授权动作不能被默认隐藏。详细程度可以调整，但被折叠信息仍可追溯。不要把“显示模型思维”当成必须功能，也不能生成假的思维过程替代实际活动日志。

输出流式增长时，用户已向上阅读就不持续强制拉回底部；提供明确的回到最新位置入口。连续更新不要重复抢焦点或让读屏软件朗读每个 token。长报告用目录、分节、来源定位和必要图表帮助浏览，而不是用大量无意义装饰稀释信息。[K3]

## AGT-03 · 适当确认只放在需要的地方

删除、发布、批量覆盖、费用、授权或外部系统写入，明确对象、范围、后果和恢复可能性。可逆低风险操作优先直接完成并提供撤销，不给每次筛选、切换或微小样式调整加确认框。没有持久授权，不把“允许一次”改成“永远允许”。

## DAT-01 · 软件中的事实表达

显示真实单位、时间范围、数据更新时间和缺测含义。示范数据明确标为示例，不能冒充客户数、收入、模型胜率、团队评价或生产任务状态。AI 生成建议与系统确认事实区分；来源链接指向支持当前结论的证据，而不是一个看起来权威的首页。

数字是数据，不是装饰。图表不因主题配色把重要曲线变得不可见；类别较多时允许超出单强调色，使用可区分的调色并配标签。长表格提供排序/筛选等任务需要的功能，不强迫改成难以比较的大卡片。

## CMP-04 · 自动命名是可编辑的辅助元数据

适用：保存常用语、创建笔记、会话或报告时，产品确实提供自动标题。MUST 把内容保存和标题生成视为可独立失败的过程；标题生成慢或失败时，不应无理由阻塞已经可保存的正文。使用中性的临时名称，允许用户稍后编辑。

MUST 尊重用户手动命名。发起生成后用户已经改名，返回值不能静默覆盖新名称。实现可记录标题来源、对象 ID 与请求/版本标识；这只是可选实现思路，不强迫迁移既有数据模型。用户切换对象、删除对象或撤销后，旧请求不得把标题写回另一个对象。

| 情形 | 应有结果 |
|---|---|
| 保存成功、标题生成中 | 内容可访问；显示稳定临时名或明确生成状态 |
| 标题服务失败 | 内容和手动命名可用；不把整个保存标为失败 |
| 用户改名后生成返回 | 保留用户名字；需要时提供可选建议，不替换 |
| 对象已切换/删除 | 丢弃不再匹配当前目标的结果 |

SHOULD 分别验证生成失败、迟到响应和手动改名竞态。K9 只描述自动标题这个交互；上述恢复与竞态约束是本项目原创扩展。[K9]

## CMP-05 · 输入建议与执行动作分开

适用：输入框有提示词匹配、常用内容或自动补全。SHOULD 默认把选择建议设计为填入可编辑内容；如果选择会立即发送或执行，MUST 用明确的行动文案/上下文说明，不把普通候选行伪装成无副作用的文本选择。

保留用户修改，除非用户明确要求替换。区分“正在输入”“候选高亮”“确认候选”“发送请求”；组合输入确认不能误触发送。只有实际采用组合框时使用对应 APG 语义，不给所有建议按钮添加 `combobox`。Esc 关闭建议，不清空草稿；Tab 保持可预测的焦点路径。[N9]

异步匹配返回时核对请求对应的当前输入和目标，避免旧候选覆盖新输入。没有结果、加载中和服务失败分别表达。候选太长可展开/查看，不能省略掉会改变执行含义的关键部分。实际产品明确采用其他交互模型时，按它的契约实现并检查。

来源是 K10-R1 汇编中的对应章节，不是尚未取得的 K10 原帖全文。编辑/执行区分与错误处理是本项目迁移规则，不能据案例文字宣称其原产品已实现这些细节。[K10-R1]

## AGT-04 · 快速结果不是取消任务的别名

适用：后端真实提供不同计算范围、质量或耗时模式。MUST 把以下动作区分：

| 动作 | 表达与状态要求 |
|---|---|
| 继续完整处理 | 保留当前目标与已产生结果，不制造额外授权 |
| 改为快速结果 | 说明实际已知的范围变化，例如减少检索深度；不虚构质量差值或完成时间 |
| 停止显示输出 | 说明仅影响前端展示；后端可能继续，不宣称取消 |
| 取消执行 | 发出取消请求后先进入 cancelling；收到执行端确认才显示 cancelled |

MUST 只显示后端支持的控制。运行中能否切换、是否要重启、是否保留部分结果，以接口契约为准；存在新增费用或外部副作用时明确说明并遵守授权。切换失败保留原始输入和已知任务状态，不把按钮文案变化当作操作成功。

SHOULD 保持部分结果可辨认其生成模式/范围，避免把快速结果标作“完整报告”。无多模式能力时不添加空壳切换器。K8 的历史短文只提供跳过入口的设计启发，未证明后端实现；本表属于原创状态约束。[K8]

## COPY-01 · 品牌语气不能替代交易事实

适用：购买、订阅、赞助或付费额度页面。MAY 使用与产品一致的生活化表达，但 MUST 在实际确认动作前，以可见且清楚的文字呈现交易性质、金额与币种、权益范围、计费周期以及是否自动续费等实际相关事实。未知信息不能猜填；只做前端时用明确示例或阻止真实确认，并说明接口缺口。

“加油”“支持”“解锁”等隐喻不能让用户误判这是一次性支付还是持续订阅。确认按钮说明真实动作；可爱插画不替代费用说明，也不把不重要选项做得醒目而隐藏关键条件。支付 pending/failed/succeeded 必须由支付结果驱动，不把点击按钮或播放动画当作付款成功。

这些是本项目的透明表达要求，不是对任何地区法规的完整概括。K11 是 2024 年历史文案案例，不用于描述当前 Kimi 的价格或会员政策。[K11]
