# 4. Agent 的实施流程

## 从设计依据到可维护实现

**材料线索**：Kimi 官网重构案例将既有规范、共享实现和检查联系起来；样式提取工具记录的是特定页面的观察值。[K4] [S9]

**综合判断**：设计规则需要在现有结构里形成可维护的约定。单张截图只能支持其中的可见部分，不能替代数据、状态或组件契约。

**如何应用**：设置页调整间距时，先定位共享表单组件和语义变量；解释哪些关系需要变化，再改最小范围。整体改版才需要更完整的设计契约。框架和工具由项目决定。

**如何检验**：检查主路径及共享改动影响的页面，比较真实内容与错误态。验证通过后交付，不以额外流程或文件数量作为完成标准。


## RUN-01 · 根据任务大小选择路径

**新建页面**：理解 brief → 确定页面类型和视觉方向 → 小范围真实内容布局 → 实现组件和状态 → 浏览器检查 → 修复已发现问题。

**既有页面改版**：读原实现/规则与截图 → 列出需保留的交互和共享依赖 → 修改最小必要范围 → 比较前后 → 回归相关页面。不能只改截图所在文件而漏掉被共享 token 影响的其他页面。

**局部修复**：先复现具体问题，直接修复并验证，不为了流程完整而重建主题、加入 UI 框架或重写架构。

**只审查**：给出证据化问题清单，不修改文件。审查模式不是自动重设计的授权。

## RUN-02 · 用小型设计契约代替模糊形容词

新建或整体重设计时，写项目级 `DESIGN.md`：用户任务、页面类型、采用的主题/已有系统、关键 token、布局、组件状态、内容与资源边界、验收条件。模板在 `templates/DESIGN.template.md`。如果项目已有该文件，则按范围更新，而不是另建相互矛盾的第二份。

不要每轮自动生成多个计划文件。正常实现不要求固定数目的子代理、来源、截图、评审轮次或设计方案。只有存在真正不同的目标解法时才比较候选；选定后进入代码实现，不停留在输出提示词。

## RUN-03 · 从可信设计输入到代码

有用户提供的截图/Figma/代码时，记录目标版本和要借鉴的属性。截图可以指导可见布局，不能证明不可见的交互与错误状态。没有截图就基于文字 brief 设计，不捏造一张“已批准”的参考图。

若提取网页样式，把计算样式视为观察值：它只代表特定页面、视口、状态和版本。没有采集到的暗色、hover、移动端或 Canvas 内容不能补猜成实测。跨页面可复用规则需要额外确认。[S9]

Kimi 的官网案例强调把已有设计、共享实现与实际验证联系起来；本规范采用这种有真实输入的工作方式，不要求特定模型、Figma 账号或内部工具。[K4]

## RUN-04 · 代码组织

复用现有组件和设计变量。基础 token → 语义 token → 组件样式形成清楚映射；共享 token 修改要检查受影响范围。CSS 选择器控制作用域，避免全局 `button`、`h1` 等改变嵌入组件。根据既有代码使用 CSS、Tailwind、CSS Modules 或其他方案，不为使用本 Skill 迁移框架。

本包 CSS 是**显式选择主题后才生效的可选资产**，不是强制全局 reset。导入前核对名称冲突；`--hf-*` 前缀用于减少冲突。不在现有 `--primary` 上直接覆盖整套值；需要适配时在项目主题层明确映射。

输入边界、API 状态和组件状态有可检查的类型/契约。复杂交互优先使用现有可靠部件；安装新依赖需要与项目约束一致，并核对版本、许可证及必要性。没有核验不要把某个版本写成唯一兼容要求。

## RUN-05 · 内容先进入布局

使用真实或明确标示的示例内容，包括长中文标题、较长英文名、负值、缺测、空结果、极端标签数量和多行描述。不能只用“标题/描述/按钮”占位后就判断版式完成。

表格、富文本、Markdown、代码块和外部内容涉及输入处理时，采用项目已有的安全渲染与清理策略；不因为样式漂亮就把不可信 HTML 原样注入。不要在日志、截图或示例中保留真实凭证和隐私数据。

## RUN-06 · 响应式与系统行为

布局使用可收缩轨道与 `min-inline-size: 0` 等必要约束，不靠 `overflow: hidden` 掩盖所有错误。列表、工作区、模态之间明确谁滚动；窄窗口下主任务可用，软键盘不会挡住关键输入与动作。桌面壳应用额外检查缩放、窗口最小尺寸、系统菜单与原生交互；不能只看浏览器全屏截图。

触屏没有 hover，关键动作应可见或有等价操作；键盘不依赖鼠标经过才能看到控件。高对比/forced-colors 模式保持可识别的控件与焦点，不强制清除用户系统色。

## RUN-07 · 性能与动效预算

先观察现有负载与目标设备，不统一强制任意压缩字节数。按需加载重型编辑器/图表，避免为了一个浮层引入整套动画运行时；图片有尺寸约束，字体只引入实际使用且许可明确的资源。特效不能持续占用本应安静工作的页面。

Web Vitals 的良好参考值为 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1，应结合现场第 75 百分位与设备分组判断。它们是性能评价口径，不是一次本地 Lighthouse 截图就能证明的生产承诺。本包没有声称任何实际网站达到这些指标。[N12]

## RUN-08 · 有问题才继续修复

浏览器检查发现问题时记录页面、视口、状态、复现步骤、预期/实际行为、修改和复验结果。完成验收且无新问题后结束；不要为了体现认真而重复无关验证。无法启动应用时完成能做的静态检查，并明确哪些视觉/交互结果未验证，不能将静态 lint 通过描述成页面验收通过。

交付包含实际改动文件、真实运行命令、检查结果和剩余限制。模拟 API、示例数据、未接通按钮必须明示。用户要代码就交付代码，不仅给另一个 Agent 的提示词。
