# 5. 可访问性与验收

## A11Y-01 · 底线与边界

适用页面以 WCAG 2.2 AA 为目标，但这里不是全部成功准则的逐项认证清单。W3C Understanding 文档和 APG 是解释/实现指导；完整合规结论仍要依据适用的规范与全面测试。

| 检查 | 基线 | 易误用之处 |
|---|---|---|
| 文字对比度 | 普通文字 ≥4.5:1；符合大字定义时 ≥3:1 [N2] | 不能四舍五入后把 4.499 当通过；placeholder 也不是自动豁免 |
| 非文字信息 | 识别控件/状态所必需的视觉信息、适用图形与相邻颜色 ≥3:1 [N3] | 不表示所有装饰分隔线都必须 3:1；弱线不能担任唯一必要边界 |
| 点击目标 | AA 2.5.8 为 24×24 CSS px 或满足规定例外 [N4] | 44×44 是本包面向触屏的推荐起点，不冒称 AA 的统一数值 |
| 键盘焦点 | 可见、顺序合理，获得焦点的组件不被作者内容完全遮挡 [N7] | 本包建议关键交互完全露出，比“不能完全遮挡”的最低条件更强 |
| 重排 | 在对应 320 CSS px 宽度等条件下保持内容/功能，必要二维内容有例外 [N5] | 局部数据表滚动不等于允许整站横向溢出 |
| 异步状态 | 状态可由语义/属性被辅助技术感知，无需获得焦点 [N6] | 不能为每次 token 更新强制抢焦点或反复打断朗读 |

大字的判断涉及字重、字号与 CJK 等效大小；14px 的普通按钮文案不能享受 3:1 放宽。不可用控件、装饰和标志有特定例外，但不能用“品牌要求”把正常信息文字排除出去。[N2]

## A11Y-02 · 可操作的检查

用键盘走完主要任务：进入页面、定位主区、输入、提交、处理错误、开关模态、返回原任务。检查所有有动作的图标是否有可访问名称；当前页、选中态、展开态是否与视觉一致。使用原生 HTML 后仍要测试实际组合结果。

模态与非模态分开；模态焦点限制及关闭后的归还应当可预测。列表建议、标签页等复杂组件使用相应键盘模型，不用随意添加 ARIA role 来替代真实行为。[N8] [N9] [N10]

DEFAULT 焦点可用 2px 实线加 2px 外偏移起步，并检查相邻背景；该数值是本包实现选择，不是对 AA 所有焦点的完整定义。不要全局删掉 outline，再忘记提供等效样式。

## QA-01 · 验收按风险选择

每个修改至少验证本次触及的主要任务与最可能受影响的状态。新建应用或主题层修改，需要更广的覆盖；改单个文案无需假装跑过所有平台。

| 维度 | 应执行的代表性检查 | 证据 |
|---|---|---|
| 范围 | 只修改授权内容；共享组件没有意外漂移 | diff 与受影响页面 |
| 视觉 | 真实内容层级、对齐、行长、密度、重要动作 | 对应视口截图与观察记录 |
| 布局 | 目标桌面、窄窗口、必要移动宽度、放大后重排 | 无裁切/遮挡，局部滚动范围明确 |
| 输入 | 长中英文、组合输入、错误、空结果 | 操作步骤和输出 |
| 异步 | 真实加载、失败、取消边界、重试 | 状态转换与草稿保留 |
| 访问 | 键盘、焦点、控件名称、对比、减弱动画 | 自动检查 + 必要手工路径 |
| 回归 | 项目已有构建/类型/测试，按改动选取 | 实际命令、退出码与失败细节 |

自动检查只覆盖它真正检测的内容。颜色 token 检查不代表所有 DOM 颜色配对；静态源码出现 `aria-label` 不代表所有图标有正确名称；通过无障碍扫描也不等于完成键盘和屏幕阅读器验证。

## QA-02 · 实际内容的边界样本

- 长中文标题、拉丁文无空格标识符、URL、emoji/罕见字导致的回退和多行标签。
- 无项目、无搜索结果、网络失败、权限不足、部分成功，以及刷新后状态。
- 触屏下原 hover 动作、键盘下弹窗、缩小窗口、文本放大、系统减弱动画。

以上是可选测试池。按功能存在与风险挑选，不要求每个静态页面模拟全部状态。浏览器自动合成的组合输入事件不等于完成真实操作系统输入法测试；应分别记录。

## QA-03 · 问题分级

**阻断**：任务不可完成、数据丢失、越权/误导性成功、关键操作无法键盘完成、关键内容无法读取。必须修复或明确阻止发布。

**重要**：真实内容溢出、主题状态不一致、错误后无恢复、必要状态不清楚、焦点被遮挡等。应在对应范围内修复。

**改进**：微小光学偏差、非关键动效或风格偏好。不得为了这些问题擅自扩大范围。

不要给未经用户研究的“高级感”打科学分数。评审可以描述风格一致性，但只有真实实验才能支持“更高转化”“更少误触”等效果结论。

## QA-04 · 交付状态必须真实

报告使用四类结果：`passed / failed / not-run / not-applicable`。没有浏览器就写视觉验收 `not-run`，不写“应该通过”。采用本 Skill 不保证任何模型必定遵循；评估用例用于后续对照测试，本次未把它们包装成已运行的多模型 benchmark。

## QA-05 · 补充模式只检查实际存在的功能

| 涉及功能 | 代表性检查 | 对应规则 |
|---|---|---|
| 自动标题 | 手动改名后旧请求返回；切换对象后迟到响应；标题服务失败 | CMP-04 |
| 输入建议 | 编辑后是否被替换；选择与发送是否混淆；组合输入；旧匹配结果 | CMP-05 |
| 快速路径 | 能力缺失、切换失败、额外费用、部分结果的范围标记 | AGT-04 |
| 付费文案 | 金额/周期/续费等实际事实是否可见；确认按钮和支付状态是否准确 | COPY-01 |
| 设计取舍 | 真实任务是否完成，人的修改/拒绝权是否可用，而非装饰数量 | CTX-06 |
| 视频参考 | 来源是否同一场；文字/画面/行为范围是否分开记录 | SRC-01 |

这些是待执行检查，不是本仓库已经跑过的下游应用测试。相应 Agent 场景见完整仓库的 evals；本 Skill 不强制为无关页面增加这些功能。
