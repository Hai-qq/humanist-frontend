# 2. 视觉系统、主题与布局

## 从品牌表达迁移到界面

**材料线索**：Anthropic 的品牌项目与团队访谈讨论整体表达和字体职责；Kimi 的品牌手册区分基础网格与表现力网格。[A1] [A2] [K1]

**综合判断**：同一个产品可同时有安静的工作区和富于表达的展示区。这里据此整理“任务决定视觉职责”的方法，不把暖色与蓝色分别当作两家公司的全部设计思想。

**如何应用**：先用一篇实际报告或一个编辑任务决定字阶、栏宽和动作位置，再选配色。阅读页可以突出正文与来源，工作台优先当前对象和可用操作，付款页优先事实与确认。若已有品牌和组件库，映射其语义角色即可，无需套用本包字体或主题。

**如何检验**：暂时去掉装饰色，主要内容和动作是否仍有层次？恢复品牌表达后，是否遮住重要状态或挤占主任务？这是一种设计检查方法，不是用户研究结果。


## VIS-01 · 两种可选方向，不自动拼接

**editorial-warm（温暖阅读型）**：柔和纸色、深色文字、节制的暖色强调；展示标题可用衬线，操作界面以清晰的无衬线为主。主要性格来自字阶、行长、留白和少量手工感视觉，而不是让所有地方都变橙色。灵感来自原品牌团队的材料与字体表达；不是原站复刻。[A1] [A2]

**precise-light（清晰轻盈型）**：接近暖白的底色、精确的网格、干净的无衬线 UI、少量蓝色状态/操作；表达性插画或动态放在确有用途的入口，而不是每个表单都播放动画。参考 Kimi 手册中品牌表现和日常工作界面的分工。[K1]

对成熟项目，默认选择 **inherit-existing**：复用现有主题而不导入这两个预设。用户明确要求融合时，以一套主题作为基础，只借用另一个方向的局部交互或排版策略，并记录哪些属性来自何处。颜色混搭不是融合策略。

## VIS-02 · 先命名语义，再指定数值

颜色至少区分画布、内容表面、悬浮表面、主/次文字、装饰分隔线、必要控件边界、品牌色、操作色、链接、焦点与反馈状态。品牌色可以和操作色不同；错误、成功、警告不能只跟着主题强调色轮换。

本包 `assets/tokens.json` 是原创、简单的项目格式；`tokens.css` 是对应生成物。它不是完整 DTCG 文件。DTCG 2025.10 是社区组规范而非 W3C Recommendation，另有明确的数据类型和值/引用模型，需要接入相关工具时再按该格式映射，不能把任意 JSON 命名为标准兼容。[N13]

下面全部为 **DEFAULT**。主题完整值与深色变体以 JSON 为唯一来源，不要修改 CSS 后忘记同步 JSON。

| 语义 | editorial-warm / light | precise-light / light | 用法 |
|---|---|---|---|
| canvas | `#FAF9F5` | `#FAFAF8` | 页面基础 |
| surface | `#FFFFFF` | `#FFFFFF` | 编辑区、输入区、局部承载 |
| surface-subtle | `#F0EDE6` | `#F0F2F4` | 次级导航、次级区域 |
| text | `#242320` | `#20242A` | 主要信息 |
| text-muted | `#625E56` | `#59616C` | 仍然需要阅读的次要信息 |
| brand-accent | `#D97757` | `#007CFF` | 品牌/装饰，不直接默认用作正文色 |
| action | `#A64B32` | `#175CD3` | 白色文字的主要按钮 |
| link | `#94412D` | `#175CD3` | 同时提供下划线等识别方式 |
| border-subtle | `#DEDAD1` | `#DCE0E5` | 非必要的区域分隔，不担当唯一控件轮廓 |
| border-control | `#8B877F` | `#7D8794` | 需要通过边界识别的输入/控件 |

## VIS-03 · 不把品牌色直接等同于合格按钮

对不透明 sRGB 色，按 WCAG 公式计算：白字在 `#D97757` 上约 **3.12:1**，在 `#007CFF` 上约 **3.94:1**，都不足以满足普通文字 4.5:1 的要求。本包相应操作色 `#A64B32`、`#175CD3` 与白字约为 **5.72:1**、**5.99:1**。前两种颜色来自公开品牌资料；配色计算是本项目完成的，不代表两家真实按钮使用了这些组合，也不是对其网站的合规判定。[S1] [K1] [N2]

MUST 对实际相邻颜色检测，包括 hover、pressed、选中、placeholder、焦点、暗色、透明叠层。只检查主按钮不能代表整个页面。提供的脚本只验证列明的纯色对，不处理照片/渐变/混色或渲染后的完整页面。

## TYP-01 · 字体按职责选择

优先已有字体与系统回退。UI、正文、展示标题、代码分开命名，不为“高级”额外引入多个字体。单一优质字体也可以形成层级。Inter、系统字体、衬线、等宽均不全局禁用；应避免的是无理由的默认和错误职责分配。[S2]

本包不含字体文件、不发起远程字体请求。默认 UI 使用 `system-ui` 及中英文系统回退；展示衬线为可选角色；等宽用于代码、路径和需要对齐的数据。名称出现在品牌资料里不构成字体嵌入或再分发授权。换字体验收时检查可用字重、数字、中文、标点与缺字回退，不能只比较英文字母。

| 角色 | DEFAULT 大小 | 默认行高 | 说明 |
|---|---:|---:|---|
| 阅读正文 | 16–18px | 中文 1.7；拉丁文 1.6 起 | 项目实际内容决定最终值 |
| UI 正文 | 14–16px | 1.5 | 密集表格与设置可用 14px，不把正文全面缩小 |
| 辅助说明 | 13px | 1.5 | 不承载唯一关键结论或错误修复指导 |
| 页面标题 | 28–36px | 1.25–1.35 | 工具页面不使用海报式巨字 |
| 展示标题 | `clamp(2rem, 5vw, 4.5rem)` | 1.1–1.25 | 英文与中文分别核验换行 |
| 区域标题 | 18–22px | 1.35 | 同层保持一致 |
| 代码 | 13–14px | 1.6 | 独立滚动；不要破坏复制内容 |

这些是起点而非普适最优值。用语义 HTML 表示标题层级，不用字号代替文档层级。

## TYP-02 · 中文不能套用英文字体微调

中文正文默认不加字距、不套用英文 ALL CAPS 标签、不盲目负字距或全段两端强制对齐。中文阅读栏先试 32–42em，英文先试 60–75ch，再用实际字号和内容检验；`ch` 是字形度量，不等于中文字符数。混排长文可选择更窄的上限。

支持中英文标点、长文件名、链接、单位、括号和多行按钮。数值列可使用 `tabular-nums`，并标清单位、时区和精度；不要为等宽感把全部说明改成 monospace。最关键的信息不能只通过省略号呈现。溢出处理提供展开、复制或独立滚动，而非无条件裁切。

## LAY-01 · 信息关系决定空间

共享对齐线比更多边框更重要。同一对象内部距离小于不同对象之间距离。DEFAULT 间距阶梯为 4、8、12、16、24、32、48、64px；图标光学校正可不落在此阶梯，但不能借机制造一堆无来源数值。

| 场景 | DEFAULT 结构 | 窄窗口处理 |
|---|---|---|
| 研究阅读 | 主要阅读栏 + 可选目录/证据栏 | 辅助栏折为抽屉；正文自然重排 |
| 多任务工作台 | 导航 224–280px；主区 `minmax(0,1fr)`；可选副区 280–400px | 先收副区，再收导航；主任务不被覆盖 |
| 设置 | 分组表单；字段说明就近 | 双列变单列，保留标签与错误关联 |
| 展示页 | 按内容选择单栏、对照或图文布局 | 保留叙述顺序，不把全部内容压缩为同样小卡片 |

断点从内容挤压与最小可用空间决定，不把 768/1024 当作品牌事实。`320 / 390 / 768 / 1280` CSS px 可作为初始检查宽度，不限制真实产品的更多目标尺寸。整页横向滚动通常需要修复；表格、代码和必要二维视图可使用局部滚动并保持可达。[N5]

## LAY-02 · 表面、圆角与图形

DEFAULT 控件圆角 8px、面板 12px、模态 16px；pill 只在状态、标签或明确设计需要时用。边框和背景要表达承载、可点击性或分组，不给所有段落包卡片。阴影首先用于浮层关系；不是禁止阴影，也不要求每张卡片都有阴影。

图标使用同一套视觉语法，常规尺寸 16/20px；小图标置于足够大的点击区。含义不明确的图标配文字或可访问名称。插画、照片、纹理和动态仅在能解释内容或承担指定品牌表达时使用；图像不可加载时，任务与信息仍然可理解。

## MOT-01 · 动效解释变化

DEFAULT 即时反馈 120ms、面板/状态过渡 180ms、较大布局过渡不超过 240ms 起步。动作响应尽快发生，不等动画完成才允许继续操作。避免所有区域进入视口都播放同一上浮效果；长期工作的主区不默认运行粒子、脉冲或连续背景动画。

用户主动触发的展开、位置变化、确认可以使用过渡，帮助看清发生了什么。`prefers-reduced-motion: reduce` 下移除非必要位移、缩放与循环，保留静态文字和状态。不要通过全局极短动画时长破坏依赖 `animationend` 的业务逻辑；业务完成必须由真实状态决定。[N11]

## VIS-04 · 深色是另一套语义映射

深色主题不能用 CSS filter 反相实现，也不能只改画布。检查浮层、禁用态、输入、图表、阴影、代码和焦点；亮色品牌素材可能需要单独版本。不自动添加用户没要求维护的模式。若已有主题切换，保持用户选择、系统默认与首次渲染一致，避免闪白或刷新后恢复错误主题。
