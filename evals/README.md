# Agent 评估协议

这 18 个场景目前是**未执行的评估设计**，不是已经通过的测试。`tests/` 中的 Python 单元测试检查安装和文件等工程行为，不能代替这里的 Agent 实际运行。

## 对照方法

选择真实可运行的 fixture，保存起始提交、数据、用户请求、工具权限、模型标识和预算。比较不加载本 Skill 与加载本 Skill；其余条件保持一致。测试重复次数根据可用预算和波动决定，不把固定次数写成所有任务的工作要求。调用付费 API 前需要明确授权。

输出匿名化后评审。功能、事实、授权、可访问性和视觉层级分开判断，不能让漂亮截图抵消数据损坏。视觉评审使用同样内容、视口和状态；同时看运行结果而不只看静态截图。评委知道哪份使用了本 Skill 会造成偏差，应尽量盲评并报告意见差异。

## 记录与判定

每个 case 记录实际触发、读取了哪些规范、改动 diff、运行命令、截图/轨迹、耗时与费用（仅记录真实可得值）。预期行为逐项记 passed/failed/not-run/not-applicable。出现 critical_failures 即不能作为该场景成功样本。

不把“没有触发 Skill”一律当失败：纯后端 case 就应该不触发。也不把阅读更多资料或使用更多 token 视为更优；评价的是完成当前授权任务的质量。

发布结论时给出样本量、模型与环境、任务差异、失败例和不确定性。没有结果之前，不宣称比官方 frontend-design 或其他项目更好。
